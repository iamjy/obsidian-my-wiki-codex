# 차량용 RISC-V 전환, 개발자가 먼저 준비할 것들

## Processed Summary

인피니언은 차세대 차량용 MCU 제품군에 RISC-V를 도입하고, 기존 TriCore 기반 AURIX TC 및 Arm 기반 TRAVEO·PSOC 라인업과 병행하는 멀티 아키텍처 전략을 제시했다. 기사에서 중요한 전환점은 코어 교체 자체보다 개발 순서의 변화다. SDV 개발 주기가 짧아지면서 개발팀은 실리콘이 나오기 전부터 가상 프로토타입에서 소프트웨어 컴포넌트, 벤치마킹, 코드 프로파일링을 진행해야 한다.

핵심 패턴은 [[automotive-risc-v-shift-left-development|차량용 RISC-V 시프트-레프트 개발]]이다. 인피니언은 RISC-V 가상 프로토타입을 디지털 트윈으로 발전시키고, 2026년 3월 DRIVECORE 소프트웨어 번들에 RISC-V 가상 프로토타입 평가 환경을 포함시킬 계획을 설명한다. 이 환경은 iLLDs, 가상 개발 키트(VDK), LLVM 기반 컴파일러, 디버그·트레이스 솔루션 등 통합 툴체인을 제공해 하드웨어 출시 전 소프트웨어 준비를 앞당기는 데 초점을 둔다.

개발팀이 관리해야 할 선행 조건은 네 가지로 정리된다. 첫째, 프리-실리콘 개발을 표준 프로세스로 편입해 부트, 기본 드라이버, 성능 프로파일링을 가상 환경의 마일스톤으로 삼아야 한다. 둘째, 컴파일러·디버그·트레이스의 툴체인 동등성을 조직의 안전 규격, 코딩 규칙, 빌드 시스템과 함께 검증해야 한다. 셋째, AUTOSAR, RTOS, 드라이버 포팅 성숙도를 일정 게이트로 관리해야 한다. 넷째, 안전·보안 요구와 인증 산출물 체계를 초기 설계 단계부터 확인해야 한다.

RISC-V 전환은 단기적으로 포팅과 검증 부담을 늘릴 수 있지만, 장기적으로는 벤더 종속을 낮추고 데이터 처리, 고대역 통신, 향후 AI 기능 같은 확장 워크로드에 대응하기 위한 산업 흐름으로 제시된다. 이는 [[edge-ai-inference-semiconductors|엣지 AI 추론 반도체]]와 마찬가지로 칩 성능만이 아니라 소프트웨어 스택, 툴체인, 제품화 생태계가 실제 채택을 좌우한다는 점을 보여준다.

## Key Claims

- 차량용 RISC-V 전환의 핵심은 코어 변경보다 실리콘 이전 단계에서 소프트웨어 완성도를 끌어올리는 개발 순서 변화다.
- SDV 개발 주기가 3-4년 수준으로 짧아지면서 가상 프로토타입 기반 프리-실리콘 개발이 중요해진다.
- 개발팀은 부트, 로우레벨 드라이버, 멀티코어 통신, 벤치마킹, 코드 프로파일링을 가상 환경에서 먼저 검증해야 한다.
- 통합 툴체인이 제공되더라도 조직별 안전 규격, 코딩 규칙, 빌드 시스템과의 결합은 별도 검증이 필요하다.
- AUTOSAR, RTOS, 드라이버, 보안·안전 라이브러리, 통신 스택의 준비 상태를 일정의 선행 조건으로 관리해야 한다.
- RISC-V는 오픈 표준 ISA와 모듈형 구조를 통해 안전, 보안, 확장성 요구에 대응할 수 있지만 포팅과 검증 부담을 동반한다.
- 개발 경쟁력은 하드웨어를 기다리는 방식에서 가상 환경에서 먼저 개발·검증하는 방식으로 전환하는 속도에 달려 있다.

## Entities

- 인피니언: 차세대 차량용 MCU 제품군에 RISC-V를 도입하고 멀티 아키텍처 전략을 추진하는 반도체 기업.
- 토마스 뵘: 인피니언 차량용 MCU 사업부문 수석부사장, SDV 시대 요구와 RISC-V 기반 MCU 전략을 설명.
- 최재홍: 인피니언 코리아 오토모티브 사업부 기술총괄 부사장, RISC-V의 오픈 표준 ISA와 안전·보안·확장성 대응을 설명.
- AURIX: 인피니언 차량용 MCU 포트폴리오, RISC-V 기반 제품군이 추가될 예정.
- TriCore: 기존 AURIX TC 계열의 프로세서 아키텍처.
- TRAVEO·PSOC: Arm 기반 인피니언 라인업.
- DRIVECORE: RISC-V 가상 프로토타입 평가 환경과 툴체인을 포함할 예정인 인피니언 소프트웨어 번들.

## Open Questions

- RISC-V 기반 AURIX 제품군의 구체 출시 시점, 기능 안전 등급, 보안 인증 범위는 추가 출처가 필요하다.
- DRIVECORE의 RISC-V 가상 프로토타입 평가 환경이 실제 ECU 개발 플로우에서 어느 수준의 정확도와 커버리지를 제공하는지는 검증이 필요하다.
- AUTOSAR, RTOS, 드라이버 포팅의 성숙도가 공급사별로 어느 정도 차이 나는지는 별도 비교가 필요하다.
